# 0022 Admin console: stack, sign-in, schema forms, CSP, local stack

- Status: Accepted (2026-11-21, M7)

## Context
Spec §10 asks for a separate console that talks only to the Admin API over HTTPS, with:
- OIDC authorization code + PKCE, with tokens in memory and never in `localStorage`;
- forms rendered from the plugins' JSON Schemas;
- a role-aware UI, where the API still enforces every permission;
- a diff and a confirmation before every publish;
- write-only secrets;
- a strict CSP with no inline scripts;
- WCAG 2.2 AA;
- Vitest, plus Playwright against the real stack in Compose.

## Decisions
- **Stack:** React 19, TypeScript 6 (strict, `noUncheckedIndexedAccess`), Vite 8, TanStack Query 5, React Router 7, pnpm.
  - TypeScript 7 and ESLint 10 are not used yet: typescript-eslint and eslint-plugin-jsx-a11y do not support them.
  - React Router 8 and jsdom 30+ need Node ≥ 22.22; the dev host and build image have 22.13.
  - All versions are pinned exactly and were at least two weeks old when chosen.
- **Sign-in:** `oidc-client-ts`.
  - The user store is an `InMemoryWebStorage`.
  - Only the transient sign-in state (state + PKCE verifier) uses `sessionStorage`, because it must survive the redirect.
  - After sign-in the tab keeps a token-free flag in `sessionStorage`. A reload then goes straight back through the IdP's SSO session (one redirect) instead of showing the sign-in screen.
  - Renewal uses refresh tokens, not hidden iframes, so the CSP needs no `frame-src`.
  - A 401 drops the session.
  - ESLint bans `localStorage`.
- **API state:** TanStack Query.
  - Writes go to the active change set, chosen in the header; its ID is kept in `sessionStorage`.
  - Every update or delete sends the ETag of the version that was loaded (`If-Match`). A 412 is explained, and the conflicting keys are listed.
- **Forms:**
  - Plugin configs render from `GET /plugins/{name}/schema`, the same file the gateway validates against.
  - A small renderer covers objects, enums, strings, numbers, optional booleans (with a "default" state), string lists, string maps, and arrays of objects. Local `$ref`s are resolved.
  - Anything it cannot express faithfully (`oneOf` of objects, pattern maps) falls back to a validated JSON field.
  - Client-side validation uses `@cfworker/json-schema`, an interpreter that needs no `eval`, so the CSP holds.
  - Core objects (routes, services, upstreams, consumers, and so on) use typed forms. Fields a form does not model stay editable as JSON under "Other fields", so nothing stored is hidden or dropped.
  - Server field errors (`routes/a.spec.plugins[1].config.limit`) are mapped to the control that holds the field, and also listed in a focused error summary.
- **Secrets:** API keys are generated by the control plane. The console shows the key once in a dialog and drops it from memory when the dialog closes.
- **Publishing:**
  - Publishing always opens a dialog with the full diff and requires ticking "I have reviewed these N changes".
  - Rollback likewise shows the inverse diff before publishing it.
- **CSP:** the production build has no inline scripts or styles: React `style` props are not used, and the preload polyfill is off. The policy, set by the static server per environment:
  - `default-src 'none'`
  - `script-src 'self'`
  - `style-src 'self'`
  - `connect-src`: self, the Admin API and the IdP
  - `frame-ancestors 'none'`
  - `require-trusted-types-for 'script'`
  - `trusted-types 'none'`
- **Serving:** the static files are served by `static-web-server`, a scratch image with no shell, running as UID 10001 with a read-only filesystem. The console is never in the gateway's request path.
  - `config.json` is mounted per environment, so one build runs everywhere.
  - The console calls the Admin API cross-origin. The control plane allows exact origins through `CP_CORS_ORIGINS` (no wildcards and no credentials, because the console sends bearer tokens, not cookies).
- **Local stack (`deployment/docker/compose.yml`):**
  - Services: etcd (TLS + auth, least-privilege users), Redis (ACL), an echo upstream, 2 gateways, the control plane, Keycloak, and the console.
  - A one-shot init service generates the dev CA, the certificates, random passwords and the Keycloak test users into the git-ignored `deployment/docker/.local/`. Nothing is hard-coded.
  - The gateway and control-plane images are JVM distributions for now. Native, distroless images come in M9.

## Consequences
- A reload costs one IdP round trip, the price of keeping tokens out of storage.
- A schema feature the renderer does not support degrades to a JSON field rather than to a wrong form.
- Dev servers (`pnpm dev`) inject an inline React Refresh preamble, so the strict CSP applies only to built assets. The e2e suite runs against the built console.
- The local stack's Keycloak runs in dev mode (H2, a single node). It is only a stand-in IdP for local work and tests.
