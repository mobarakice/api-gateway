# 0005 JSON with Jackson

- Status: Accepted (2026-11-18)

## Context
etcd values, LKG snapshots, the Admin API, and plugin configs are JSON. The library must work under Native Image and must not sit in the per-request hot path except where a plugin needs body access.

## Options
1. Jackson (core + databind), which Vert.x uses as well.
2. DSL-JSON, which is compile-time and faster but has a smaller ecosystem.
3. Vert.x `JsonObject` only.

## Decision
Option 1.
- Configs are parsed into records at snapshot compile time, off the event loop.
- The request path never parses config JSON.
- Records use explicit constructors with `@JsonCreator` where needed.
- Reflection metadata for config records is generated by a reviewed registration in `gateway-app` native config, not by the tracing agent alone.

## Impact
- Performance: parsing happens only during compile (M10 benchmarks the snapshot compile).
- Memory: no runtime cost for unused databind features.
- Native Image: Jackson is covered by the reachability metadata repository. Config records need reflection registration, which is reviewed.
- Operational: none.
